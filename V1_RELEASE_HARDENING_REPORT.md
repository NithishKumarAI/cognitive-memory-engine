## 2. Confirmed issues and narrow fixes

- Frontend image had a localhost API build default and no fail-closed release validation. It now requires an explicit HTTPS origin; missing/insecure/loopback values, credentials, path/query/fragment and unrecognized `NEXT_PUBLIC_*` inputs fail validation. Loopback works only with the explicit local-test build opt-in.
- The previous Next CLI already documented support for `PORT`; an actual failure to honor that environment variable was **not** reproduced. The new startup wrapper makes the contract explicit, validates 1–65535, defaults locally to 3000 and always binds 0.0.0.0. This is an explicit, regression-tested startup contract, not a claim that Next previously ignored PORT.
- Backend already expanded PORT through its shell command. It now uses a tested Python entrypoint with the same 8000 fallback and 0.0.0.0 binding, validated input and no automatic model initialization/migration. Backend Docker now runs as UID 10001 with a writable model-cache home; frontend retains its non-root node runtime and both npm install stages retain `npm ci`.
- Home’s `?mode=voice` shortcut was ignored. Capture now focuses/highlights and scrolls to voice controls only for that valid mode with no selected capture. It does not request permission or record automatically. Invalid modes leave ordinary text entry available.
- Replaced the unpatched python-jose/ECDSA dependency surface with PyJWT while preserving HS256, signing key, subject, twelve-hour default lifetime and API bearer behavior. Expiry/subject claims must be present. No issued token from this app lacks those claims. There is no cookie/session migration or automatic key rotation.
- Updated fsspec 2026.4.0 → 2026.6.0 for its advertised security fix; verified dependency consistency and local filesystem behavior. No blind model/Torch upgrade.
- Added explicit registration and Gemini kill switches, both true by default for compatibility, with deployment instructions to set false until gates pass. RAG provider output now has a 2048-token cap; extraction/transcription retain their existing separate limits. This is not a budget or a guarantee about total billed tokens/cost; long answers may be truncated and need live-quality acceptance.
- A lock prevents concurrent cold requests from constructing duplicate embedding model instances in one process. A two-thread synthetic constructor regression proves one construction; it does not validate actual weights or memory sizing across processes/instances.

## 8. Per-finding exposure and remaining security advisories

These are code/dependency-path assessments, not exploitation proofs or owner risk acceptances.

- **python-jose / PYSEC-2026-4298 — REMOVED.** Direct runtime token issue/verify library. The advisory concerns DER asymmetric-key/HMAC confusion; this app used an explicit configured HS256 allowlist and a symmetric secret, so version alone did not prove that exploit was reachable. Replacing the library removes that unpatched surface without changing signing key or sessions. [Primary advisory](https://github.com/advisories/GHSA-3qf3-8w2g-rqmx).
- **ecdsa / PYSEC-2026-1325 — REMOVED.** jose transitive ECDSA signing/key operations have a timing risk with no advertised fix. This app’s HS256 path did not call ECDSA signing. Removal reduces unused crypto surface; it is not a claim that existing HMAC tokens were exploitable.
- **fsspec / PYSEC-2026-4217 — FIXED PIN.** Runtime transitive path through Torch/Hugging Face. Advisory involves unsandboxed templates in ReferenceFileSystem/Kerchunk documents. The application does not accept reference filesystem/model URLs from users, but the vulnerable installed pin was updated to the advertised 2026.6.0 fix. Local file IO and the full affected suite pass. Real model/cache acceptance remains unperformed.
- **braces / GHSA-vfj7-8cjw-p6xm — REMAINS.** Stack exhaustion from deeply nested glob patterns. Dev/build path: eslint-config-next → @next/eslint-plugin-next → fast-glob → micromatch → braces. All five nodes are reported high. No direct application runtime import was found and the runtime audit is clean. Attacker-controlled lint/build inputs or dependencies remain a tooling risk; use trusted reviewed source, isolated CI and no deployment credentials in untrusted jobs. No compatible published fix was found, so this needs monitored remediation or explicit owner disposition before release. [Primary advisory](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm).
- **cryptography 48.0.1 / PYSEC-2026-3554 — REMAINS.** X.509 DNS constraints/wildcard chain validation; advertised fix 49.0.0. **PYSEC-2026-3553 — REMAINS:** duplicate-certificate chain recursion/resource exhaustion; fix 49.0.0. **PYSEC-2026-3552 — REMAINS:** PKCS7 decryption oracle; fix 50.0.0. Package is a Google-auth runtime dependency; this app does not directly expose certificate-chain verification or PKCS7 decrypt endpoints and new HS256 uses HMAC. That does not prove all transitive paths unreachable. A 50.x upgrade and auth/TLS/provider compatibility evidence are required; major crypto changes were not substituted without that evidence. Public-release disposition: BLOCKED pending remediation or documented reachability review/acceptance.
- **sentence-transformers 5.5.1 / PYSEC-2026-4164 — REMAINS.** Runtime lazy embedding loader; local model-directory trust bypass, advertised fix 5.6.0. Model ID is hardcoded rather than user supplied, but a writable/tampered cache is relevant. Keep cache/assets trusted and private. Minor model-library upgrade still requires actual model load/encode/vector verification, not a fake constructor test; no live weights were downloaded for this pass. Public-release disposition: BLOCKED pending that tested upgrade or explicit acceptance.
- **torch 2.12.0 / PYSEC-2025-194 — REMAINS.** Runtime embedding inference dependency; advisory names torch.jit.script memory corruption/local execution. Application code does not call jit.script directly; transitive absence/exploitability has not been proven. Advertised fix 2.13.0 is a substantial platform/model-runtime change, not an automatic patch. Public-release disposition: BLOCKED pending verified platform/model upgrade or explicit acceptance.
- **setuptools 81.0.0 / PYSEC-2026-3447 — REMAINS.** Packaging/source-distribution exclusion bypass involving Unicode normalization; advertised fix 83.0.0. No app route builds or publishes sdists; dependency installation/build tooling is the realistic exposure. Torch 2.12 explicitly requires **setuptools<82**, so raising setuptools to 83 alone would break requirements. This is a concrete dependency constraint, not a passing-audit workaround. Resolve with the reviewed Torch/toolchain plan; do not silently force the conflicting version. Public-release disposition: unresolved tooling gate.

Full aliases/fix versions are in curated Python evidence; remaining findings were not deleted or marked false positives. Security cannot be certified by a passing suite.

## 9. Authentication and privacy release gate

**Residual-risk option B: limited-access beta safeguards, requiring owner acceptance before use.** JWTs remain in localStorage: any same-origin injected script can steal a live token and exfiltrate the user’s accessible history. Logout/401 clears local credentials and session feedback keys; it does not revoke an already-issued token on the server. Default expiry remains twelve hours and the signing key is preserved. No server-side token revocation, refresh rotation, strict CSP or automatic retention/account-erasure mechanism is supplied. Normal expired tokens and invalid signatures are rejected; safe dashboard-only redirects, no-store auth responses and server-side owner checks remain verified.

For a limited beta, close registration, restrict access at an authenticated gateway/VPN/allowlist, use HTTPS with exact CORS origins and short owner-approved session lifetime for newly issued tokens, allow only trusted assets/source/builds, avoid third-party scripts, keep shared caches private, monitor sanitized security events and document reauthentication/incident response. Shortening the configured lifetime does not invalidate older tokens. Do not change the existing signing key incidentally during library replacement; any rotation must include an explicit user-session recovery plan. A closed registration endpoint alone does not restrict existing users or brute-force login attempts. Compensating safeguards reduce exposure; they do not make localStorage equivalent to HttpOnly sessions or close public-release gates automatically.

React renders saved text as text; unsupported citation IDs stay unlinked. Retrieved content and questions remain untrusted model inputs. Owner filtering and explicit confirmation prevent a model from acquiring arbitrary cross-user database access or automatically writing confirmed facts, but prompt injection can still cause inaccurate/unsupported output. There are no model tools with database credentials. Cloud voice processing still requires explicit consent and editable text before analysis. Saved text/history persists without an automatic retention policy; raw audio is not an application learning record. Provider retention, database backups, logs and deletion obligations require environment-specific approval.

A future cookie/CSP migration needs separately approved design, HttpOnly/Secure/SameSite cookies, CSRF/CORS changes, expiration/rotation/revocation, tested migration/session recovery and nonce/hash handling for the inline theme script. That migration was not partially shipped here. Authentication is not certified production-secure.

New controls: Gemini call kill switch, registration closure, 2048-token RAG output cap and one model initialization per process at cold start.

**Not implemented/configured:** distributed per-user rate/budget reservations, daily/monthly reset accounting, global request-body limit before JSON parsing, distributed Gemini concurrency limits, external gateway rules, actual Cloud Run scaling limits or provider-project quotas/spend response. Registration/login fields still need ingress/body/abuse controls. Existing `UsageLimit` contains unique user ID, daily/monthly counters and created_at, but no enforcement, increment or window-reset path. It was not activated, reset, backfilled or erased; there is no new quota mechanism whose success/failure billing semantics could be claimed.

Defaults for switches are true to preserve compatibility. The disabled Gemini revision never constructs a provider client, but local embeddings/model downloads remain available; old revisions/in-flight calls may finish. Neither switches nor output caps prevent unlimited repeated paid calls when enabled. Provider failures/timeouts may already have consumed billable work. Cloud scaling bounds and CORS are not user budgets. Before enabling public AI, configure authenticated gateway/distributed limits, provider request/token limits, reviewed daily spend response and monitoring, plus closed registration until beta access controls are ready. Alerts-only billing budgets are notifications, not an enforced spending cap; verify any service-supported cap separately. See [Cloud Billing budget behavior](https://docs.cloud.google.com/billing/docs/how-to/budgets). The unexecuted deployment plan defines atomic reservation/reset/failure requirements for a future durable limiter without building billing here.
